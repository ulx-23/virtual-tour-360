# Migrasi MySQL ke Supabase PostgreSQL

Status: **Tahap 1, audit selesai; belum ada perubahan database atau konfigurasi runtime.**

## Audit kompatibilitas (6 November 2026)

### Proyek dan versi

- Proyek Next.js App Router yang sudah ada. `package.json` memasang Next.js 16.4.3, React 19.3.0, Prisma CLI dan Client `^6.4.1`, TypeScript `^5`, Sharp 0.35.x, serta Vitest 5.x. Node lokal v24.14.1; `@types/node` menargetkan 20 dan belum ada `engines.node` yang membatasi versi deploy.
- Database di `prisma/schema.prisma` memakai `provider = "mysql"` dan `DATABASE_URL`. Tidak ada `prisma.config.ts` atau direktori `prisma/migrations`. Dokumentasi menyebut skema awal diterapkan dengan schema push; karena itu tidak tersedia riwayat migration MySQL yang dapat diarsipkan. Cadangan skema dan dump database sumber harus dibuat sebelum mengubah provider.
- Ada 20 model dan 9 enum. Kelompok relasi: User/Role/Permission dengan tabel penghubung RBAC; Tour/Scene/Hotspot/Building/Floor/FloorPlan/Marker; MediaAsset/PanoramaAsset; TourPublication/TourView/ExportJob; SiteSetting/PageSection/AuditLog. UUID adalah `String @default(uuid())`, sehingga ID sumber dapat disalin apa adanya. `Tour.startSceneId` membuat siklus FK nullable dengan `Scene.tourId`; transfer data perlu dua tahap atau penundaan constraint yang direncanakan.
- Native type `@db.LongText` pada `TourPublication.snapshotJson` khusus MySQL dan harus diganti tipe PostgreSQL yang sesuai (`@db.Text`). Semua `@db.Text` lain perlu divalidasi pada provider baru. Enum Prisma akan menjadi enum PostgreSQL; pertahankan nama serta nilainya. Periksa `@map`, `@@map`, unique, indeks, `onDelete`, default dan timestamp pada SQL hasil migrasi sebelum diterapkan.
- Tidak ditemukan pemakaian `$queryRaw`/`$executeRaw` atau sintaks SQL khusus MySQL dalam kode aplikasi dan skema. Perbedaan kolasi/case sensitivity MySQL vs PostgreSQL tetap berisiko untuk email, slug, dan pencarian teks; uji data sumber yang berbeda hanya pada kapitalisasi. Kolom `fileSize`/`ExportJob.fileSize` bertipe `Int`; ukur berkas sebelum transfer jika ada yang melebihi batas integer 32-bit.

### Autentikasi, API, dan file

- Login memakai bcrypt, JWT cookie, serta Prisma; logout menghapus cookie. RBAC mengambil role dan permission dari database. CRUD user admin tersedia, tetapi tidak ditemukan endpoint registrasi publik. Verifikasi register harus mengacu pada alur pembuatan user admin yang ada, kecuali produk memang memerlukan registrasi publik. `JWT_SECRET` mempunyai fallback hardcoded: wajib tetapkan secret kuat di Vercel sebelum deploy; pertahankan secret lama agar sesi yang masih aktif tetap valid.
- Semua endpoint database memakai Prisma Client; tidak ada ketergantungan langsung pada driver MySQL. Namun URL media dirangkai sebagai `/${storageKey}` di sejumlah halaman, layanan publikasi, dan ekspor. Jangan mengganti key/URL secara sepihak saat transfer.
- `src/lib/storage.ts` menyimpan panorama dan thumbnail di `public/uploads`; avatar menulis langsung ke `public/uploads/avatars`. Ekspor ZIP dan backup ditulis ke `public/exports`, dibaca kembali dari disk, dan job dijalankan dengan `setImmediate`. Pendekatan ini tidak dapat diandalkan pada filesystem dan umur proses fungsi Vercel. Perlu object storage persisten serta pemrosesan ekspor yang dapat ditunggu atau dijalankan oleh worker/queue yang sesuai. Paket standalone tetap harus berisi `window.TOUR_DATA`, aset lokal, dan dapat berjalan tanpa API/database.
- Direktori kerja saat audit berisi 105 file unggahan sekitar 18.1 MB serta 131 arsip ekspor sekitar 19.5 MB. Keduanya belum terlacak Git. `*.env` diabaikan Git, termasuk `.env.example`; file contoh konfigurasi saat ini tidak akan ikut deploy dari Git. Jangan commit unggahan, arsip, dump, atau kredensial. Status Git memiliki banyak perubahan lain yang sudah ada; jangan menimpa pekerjaan tersebut.
- Batas ukuran request, durasi fungsi, dan kuota Supabase Storage/Vercel Hobby perlu dicocokkan dengan panorama hingga 50 MB per file dan backup ZIP hingga 250 MB. Pemeriksaan batas layanan harus dilakukan saat menentukan alur unggah dan ekspor.
- Log pengembangan yang diberikan setelah audit menunjukkan `PrismaClientInitializationError` saat halaman utama membaca `SiteSetting` dan `Tour`: koneksi ke MySQL `127.0.0.1:3306` gagal karena proses MySQL lokal tidak aktif. MySQL 8.0.30 kemudian dijalankan dengan konfigurasi Laragon yang ada; koneksi TCP, query baca ke 20 tabel, dan respons HTTP 200 halaman utama berhasil. Error hidrasi pada log memiliki atribut tambahan `cz-shortcut-listen` pada `<body>`, yang mengarah pada modifikasi DOM oleh ekstensi browser dan tidak membuktikan masalah database. Peringatan `allowedDevOrigins` berlaku saat membuka dev server lewat IP LAN `192.168.0.105`, terpisah dari koneksi MySQL.
- `prisma/seed-demo.ts` memanggil `prisma.tour.deleteMany` untuk slug tur demo sebelum membuat data baru. **Jangan jalankan skrip ini pada database sumber atau target berisi data** dalam proses migrasi; ia dapat menghapus tur beserta relasi yang memakai cascade. Script ini juga menulis panorama demo langsung ke `public/uploads` dan tidak cocok untuk runtime Vercel.

### Kesimpulan audit

Migrasi skema **memungkinkan tanpa mengganti Prisma atau mengubah UI**, tetapi pergantian provider saja belum cukup untuk deploy yang utuh. Database MySQL lokal kini dapat dibaca dan berisi 20 tabel; jumlah baris per tabel, ukuran media yang terkait record, serta akses ke proyek Supabase belum diverifikasi. Integritas data dan koneksi target belum dapat dinyatakan lolos.

## Rencana dan gerbang verifikasi

1. **Backup sumber.** Akses MySQL lokal telah pulih. Simpan salinan skema saat ini, konfigurasi tanpa secret, dump MySQL konsisten yang mencakup semua tabel, serta salinan unggahan di lokasi aman pada D:. Catat checksum, jumlah baris per tabel, daftar ID/FK, dan key aset. Pastikan dump serta URL berpassword tidak masuk Git. Tidak ada reset atau penghapusan data.
2. **Siapkan skema PostgreSQL.** Pertahankan Prisma 6, sesuaikan provider dan native type, serta tambahkan `directUrl` untuk koneksi migration jika konfigurasi Supabase memerlukannya. Hasilkan baseline migration PostgreSQL baru dari skema kosong, tinjau SQL enum, FK siklik, indeks, dan perilaku `onDelete`; jangan gunakan migration MySQL pada PostgreSQL. `prisma migrate deploy` hanya setelah SQL dan target diperiksa.
3. **Pindahkan data.** Ekspor semua tabel MySQL dengan ID asli; impor ke PostgreSQL dalam urutan relasi, atur `startSceneId` setelah Scene tersedia, lalu cocokkan jumlah baris, ID, FK, nilai enum, snapshot publikasi, timestamp, serta hasil query aplikasi. Hindari seed yang menimpa user/data produksi. Bila terjadi kegagalan, hentikan cutover dan biarkan MySQL sumber tidak berubah.
4. **Koneksi Supabase.** Gunakan URL pooler transaksi yang direkomendasikan Supabase untuk runtime Vercel dan URL koneksi langsung/session yang sesuai untuk Prisma Migrate; uji kompatibilitas pooler dan SSL dengan Prisma 6. Simpan `DATABASE_URL`, `DIRECT_URL` (jika digunakan), `JWT_SECRET`, serta kredensial Storage sebagai environment variables server saja. Jangan gunakan awalan `NEXT_PUBLIC_` untuk secret atau service-role key.
5. **Pindahkan file.** Buat adapter Storage untuk baca/tulis/hapus; transfer panorama, thumbnail, floor plan, dan avatar dengan pemetaan key yang mempertahankan URL publik atau memperbarui semua pembentuk URL. Verifikasi setiap key database menunjuk objek yang ada. Ubah generator dan unduhan ZIP agar bekerja dengan object storage serta waktu eksekusi Vercel; tetap simpan file sementara hanya pada lokasi yang diizinkan lingkungan dan tidak mengandalkannya untuk request berikutnya.
6. **Uji sebelum cutover.** Jalankan `prisma validate`, generate, typecheck, lint, seluruh Vitest, build produksi, lalu uji integrasi dengan database staging: login/logout, alur user admin dan RBAC, seluruh CRUD, upload/hapus media, editor, hotspot, publikasi, impor backup, ekspor standalone/offline, serta endpoint unduhan. Uji restore dari backup dan pemeriksaan jumlah baris/relasi.
7. **Deploy.** Terapkan migration yang telah ditinjau ke target kosong melalui proses terpisah dari build Vercel; isi environment variables Production/Preview; verifikasi aplikasi terkoneksi ke Supabase. Bekukan penulisan MySQL hanya saat cutover terjadwal, jalankan delta transfer bila perlu, uji smoke, lalu alihkan trafik. Pertahankan MySQL dan file sumber untuk rollback sampai pemeriksaan selesai.

## Catatan eksekusi

- Audit awal hanya membaca kode, dokumentasi, dan metadata file. Lanjutan pemulihan koneksi dan backup tidak menjalankan `prisma migrate`, `db push`, database reset, impor, atau operasi tulis tabel aplikasi.
- Lanjutan setelah error koneksi: MySQL 8.0.30 lokal dijalankan tanpa mengubah skema. Backup sumber dibuat di `.migration-backups/mysql-2026-11-06/` dan diabaikan Git: dump konsisten `virtual_tour_360.mysql.sql` (67.945 byte, SHA-256 `DD7C3AEC64ADB5D0E8F46BB52B4CEA2D025981C57BFDAF2F2CDDB2A473FC7E4A`), salinan skema, konfigurasi sumber privat, 105 unggahan, dan 131 arsip ekspor. Dump berisi 20 `CREATE TABLE`, 9 blok `INSERT`, dan penanda selesai. Backup belum diuji restore; jangan menganggapnya valid untuk pemulihan sampai uji restore pada database terpisah berhasil.
- Hitungan baca cepat dari database sumber saat backup: `users=3`, `tours=0`, `scenes=0`, `hotspots=0`, `media_assets=75`, `panorama_assets=75`, `tour_publications=0`, `roles=4`, `permissions=18`, `site_settings=7`. Artinya file media saat ini tidak memiliki tur aktif di database yang terhubung; sebelum transfer, pastikan database sumber ini memang sumber data yang dimaksud.
- Perintah audit: `rg --files`, `rg -n`, `git status --short`, `git ls-files`, pemeriksaan `package.json`, `prisma/schema.prisma`, dokumen proyek, dan pembacaan kode layanan. `npx prisma validate` berhasil pada skema MySQL saat ini. Verifikasi skema PostgreSQL, kode, dan migrasi pada tahap berikutnya masih tertunda.
- Pemulihan bila tahapan berikutnya gagal: jangan ubah sumber MySQL; arahkan runtime kembali ke URL MySQL lama hanya bersama kode/skema versi MySQL yang dicadangkan, dan pulihkan key aset lama dari salinan unggahan. Jangan menggunakan `migrate reset` pada database berisi data.
